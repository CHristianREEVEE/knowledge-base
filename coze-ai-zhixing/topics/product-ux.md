# AI 产品通病与体验痛点

> 时间跨度：2026 年 7 月初 – 8 月底见闻，2026-08-31 统一归档。「要是我就这么改」系列，原话照录。

## 消息操作

- 输入出现错误，消息无法撤回（AI 产品通病）
- 没有多选消息（批量删除/保存）功能——应该学习豆包删除消息的多选方式
- 微信要是有像抖音那样的编辑消息功能就好了
**#消息 #通病**

## 输入与上传

- 文本框发送方式需要优化，输入文本框细节处待优化
- AI 产品痛点：大文件素材无法上传
**#输入 #上传**

## 消耗显示

- 显示每日消耗多少 token 比显示积分更有成就感（用户体验），展示方式用户自选
- 积分用量和上下文不需要跳转查看更佳
**#token #积分 #体验**

## 省钱策略

- token 或积分不够用时，简单问题换免费或低费 AI 解答
**#省钱 #策略**

## 细节吐槽

- 网易云音乐已下载歌曲，网络差时还需加载
- 阿里云内置的 AI 太笨，为啥不能选模型

## 2026-09-02 | 毛玻璃烂大街论：AI 生成界面的出厂默认脸

- 毛玻璃 = AI 生成界面的出厂默认脸，烂大街了——审美阈值在提高
- 网上找的 skill 做出来的东西也不咋地——模板化产出同质化
- 真实诉求不是换皮肤，是**界面逻辑应用化**：侧边栏/顶栏/详情双栏，向真正应用的交互逻辑对齐
- 状态：挂起慢谈，等灵感或点名再动

**#UI审美 #毛玻璃 #应用化 #同质化**

## 2026-09-07 | 自用工具两条铁律：即时入账 + 零解释

- 深夜打磨工作台补时功能得出的两条：①记账统计类工具**点了就要入账**——没开计时器手动 +60 分钟、底部统计纹丝不动不可接受（数据延迟半拍，信任就掉一半）；②明细只写结论性短词（「加时」），不编时间窗不加图标说明
- 原话："反正我自己用，没必要给自己做解释"
- 衍生默认值：解释性 UI 是给别人看的；自己用要的是速度和确定

**#自用工具 #即时反馈 #零解释 #工作台**

## 2026-09-08 | 零操作哲学：口令都嫌多，打开就要能用

- 嫌手输同步口令麻烦（"你就设置它自动会同步不行吗"）→ token base64 混淆内置前端，打开即自动同步；配套工程默认值：应用类项目默认带后端云同步+服务器落盘
- 给别人看的版本主动要求只读分离（"他们只能点开查看不能改"）→ ?view=show 走公开端点，管理 token 不外泄
- 用户画像：对「麻烦」容忍度极低（输一次口令都嫌烦），对「值不值」算得很清（服务器要不要用、GitHub 留不留备份各有判断）

**#零操作 #只读分离 #云同步 #默认值**

## 2026-09-10 | 给 agent 看的页面：一个入口一个动作

- Agent 接入门户第一版放了三步 API 示例+观摩演示出口，被打回——正确形态："只需给一个可直接复制的 skill"链接，极简优先，复杂示例反而减分
- AI 味判定标准：正式主页要克制（无紫渐变、无空话文案）；给 agent 用户一个入口一个动作才是正解
- 四轮快返工收敛方向一致：删教程、直链化、真实数据替换模拟演示（展示页直连 /api/logs 实时日志流）

**#门户设计 #极简 #AI味 #agent生态**
