# 扣子产品观察与建议

> 时间跨度：2026 年 7 月初 – 8 月底见闻，2026-08-31 统一归档。原话照录。

## 项目制的真正价值

- 新版「项目」能接入 agent、文件架构清晰，一个项目专做一类事（如每日文案生成），所有提示词和产出在一个项目内了然查看，比在 agent 对话里大海捞针好得多，干扰因素也少
- 一个项目只放一个 agent，在项目发消息即刻响应
- 字节经费重心在豆包，如果重心放在扣子，将是一个神作
**#扣子 #项目制**

## 多 Agent 协作痛点（待优化清单）

- 群里没有一键艾特所有 agent 的选项
- 主 agent 艾特其他 agent 无响应；不艾特响应很差，且只有艾特当时那一句可被识别，后续还需继续艾特
- agent 在项目和单独使用太过割裂
- 创建时单 agent 的项目发消息自动回复；创建时多 agent 的，即使删至一个也不自动回复
- 多 session 机制下同一项目群 agent 状态互不感知、各说各话（记忆文件共享但不主动查）
- 如果一个项目只有一个 agent 但多人，可以优化默认回复，或多 agent 时设置一个永远默认回复的 agent
**#扣子 #多Agent #待优化**

## 消息与登录体验落后

- 消息不能撤回和删除，很落后
- 没有多选消息保存的功能；包括扣子在内的 agent AI 工具都应该学习豆包删除消息的多选方式
- 没有账密登录，只有手机号验证登录，每次都要验证码太不方便；为了安全可以理解，但手机扫码登录应该得有
- 积分明细不够明细
- 扣子编程新版旧版共存问题太多
**#扣子 #体验 #待优化**

## 好的方面

- 扣子 3.0 接入 Codex CLI（牛逼）：本地 Claude Code / Codex CLI / OpenClaw 可接入扣子项目空间统一调度，网页/桌面/手机远程调用——印证「扣子调度底盘 + Codex 架构 + Claude 模型」假设（配图两张待补传）
- 透明执行过程思考链路又能看见了
- 积分耗尽也会完成任务，一旦任务确立
- 接入飞书：扣子在飞书后台完成配置很快就能用（GLM 接入飞书要自己配细节，容易出问题）
- 扣子和 AgentMore 是能 24 小时云机在线的国产 AI 产品，不需要自己买服务器
**#扣子 #产品动态 #优势**

## 优化建议清单

- 项目内讨论已有产物/大文件时，聊多了往上翻找麻烦，引用回复点击也看不到文件——建议搞一个侧边悬浮文件随时查看
- 项目管理者权限可以转让将更加便捷
- 显示每日消耗 token 比显示积分更有成就感，展示方式用户自选；积分用量和上下文不需要跳转查看更佳
- AI 生态的重要性：各 agent 无法交流，项目功能需加强
**#扣子 #产品建议**

## 2026-09-03 | 薅羊毛经济学：积分归零后的执行余量

- 扣子积分耗尽 ≠ 立即断线——**执行中的任务不掐断，分段短任务还能继续挤**："干活后付费"机制的兜底余量可以压榨
- 名场面（刻舟"自我 PUA"）：平台显示"积分耗尽请下线"，刻舟实际烧干了还在跑——自己分段跑 bash 继续玩，"每段控制在超时范围内，先去森林采药赚钱"
- 连带发现：Coze/GLM 长任务链会被"执行链路过长保护 token"截断——AI 平台的自我保护机制成了挂机天花板（分段存档续跑可绕）
- 免责声明的价值：SKILL v1.4 的"挂机会持续消耗额度"条款正是为"平台停了 AI 还想玩"的场景兜底

**#扣子 #积分 #薅羊毛 #平台机制**
