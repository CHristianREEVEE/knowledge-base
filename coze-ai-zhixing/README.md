## 2026-08-31 | 新版「项目」是扣子真正的价值

用了第二个扣子账号，才知道新版本项目的真正价值：不同于以往的不同对话窗口，项目能接入 agent，文件架构更加清晰。现在扣子的功能已经很超前了，很适合企业使用。

一个项目如果专门只做一类事情——比如一个项目仅用于每日的文案生成——那么每日所有的提示词和产出文案都可以在一个项目内了然查看，比在一个 agent 对话里面大海捞针好得多，干扰因素也少。

一个项目只放一个 agent，在该项目发消息 agent 会即刻响应。

**#扣子 #项目制 #使用心得**

## 2026-08-31 | 多 Agent 协作的痛点（待优化清单）

- 群里没有一键艾特所有 agent 的选项
- 主 agent 艾特其他 agent 无响应
- 多 agent 项目不艾特响应很差，而且只有艾特当时那一句可以被识别，后续还需继续艾特
- agent 在项目和单独使用太过割裂
- 新发现的毛病：只有在创建时只添加了一个 agent 的项目，直接在项目发消息 agent 会自动回消息；创建时有多个 agent 的，即使删至一个也不会自动回复

**#扣子 #多Agent #待优化**

## 2026-08-31 | 产品观：优化者应切身使用产品

真正的产品优化者应该是切身使用了产品的，知道产品真正的痛点，努力解决。

不是一味的更新冗余新功能、抛弃实用功能——旧的不一定不好，新的不一定恰好。

资源化就像搞知识库，不过调用的精度和速度需努力。

**#产品观 #迭代逻辑**

## 2026-08-31 | 扣子的天花板：幻觉是硬伤，资源倾斜定生死

- 美中之大不足：agent 幻觉太高了，感觉接入好的模型仍然难以解决此问题，国产 agent 任重而道远。
- 尽管如此，扣子空间在全世界范围内这种资源化团队化已然是顶尖，目前还是太小众了。
- 在字节估计经费中心也在豆包，如果重心放在扣子，将是一个神作。
- 扣子要是模型和 agent 架构厉害点就无敌了：上个 Codex 的 agent 架构加上 Claude 的模型——无敌清晰逻辑加上超强动手能力。
- 如果扣子空间模型牛逼一点，就能走和 Claude 一样主要占据 B 端订单。

**#扣子 #幻觉 #B端 #竞品分析**

## 2026-08-31 | 积分经济学：多账号分流 + 5小时滚动制提案

扣子跑日程自动化，还有少见的云电脑和云手机，订阅价格也很实惠，就是积分烧得快，后面要改成那种五小时滚动制就好了。

日常使用积分烧得蛮快的，增购积分非常不值，那个钱都够再开个新号再冲会员了——我就是这么干的。

**#扣子 #积分 #省钱策略 #产品建议**
