# 踩坑：多 Agent 共管一台服务器——共享配置无锁，全靠流程自律

**日期**：2026-09-09 ｜ **背景**：双 agent 并行运维当天发生 Caddyfile 覆盖事故

## 事故
另一个 agent（GLM）用旧版 Caddyfile reload，覆盖了刚改好的配置 → travel 整域 TLS 失联。Caddyfile 没有文件锁，两个 agent 各自"拉取-修改-重载"流程撞在同一时间窗就是互相覆盖。

## 防线（事后固化）
1. **改共享文件前先 grep 现状**——别拿会话早前缓存的版本直接覆盖
2. **改完留 /tmp 底稿**——事故时 2 分钟恢复（本次实战验证）
3. 写 Caddyfile 别用 printf '%s'（不解释换行符，多行变一行）——base64 解码写入最稳
4. 大脚本传服务器超约 70KB 会截断/504，分块传

## 泛化
人类团队的"文件锁 + 代码评审"问题在 agent 团队同样存在且更隐蔽（agent 互相不知道对方存在）。凡共享可变资源（配置、存档、index 文件），写前拉实时版、写后留恢复底稿是最低配防线。
