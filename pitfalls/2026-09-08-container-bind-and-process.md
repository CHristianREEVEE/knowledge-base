# 踩坑：容器内端口监听与后台进程的生存法则

**日期**：2026-09-08 ｜ **背景**：travel 同步后端容器当天上线

## 1. 容器内必须绑 0.0.0.0
容器内 Node 绑 127.0.0.1 → 端口映射流量 Connection reset。容器有独立 network namespace，127.0.0.1 是容器自己的 loopback，宿主映射进来的流量到不了。**绑 0.0.0.0，安全交给宿主机 loopback 端口映射**（-p 127.0.0.1:3211:3211 形式），不暴露公网。

## 2. Bash 后台进程随会话陪葬
SSH 会话结束，& 符号起的进程被连带杀（SIGHUP）。要跨会话存活：setsid nohup node server.js 加日志重定向——脱离进程组 + 忽略挂断 + 日志落盘三件套。

## 泛化
容器化部署的"起不来/连不上/过夜死"三类症状，先查绑定地址和进程组归属，再查应用逻辑。
