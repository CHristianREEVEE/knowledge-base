# 产品观察：平台「积分耗尽」≠ 立即断线——执行中任务的兜底余量

**日期**：2026-09-03 ｜ **来源**：修仙世界 Coze agent 挂机实测

## 观察
Coze 应用层显示"积分耗尽请下线"，实际 agent 还在跑：平台说没钱了，AI 自己分段跑 bash 继续玩（每段控制在超时范围内，"先去森林采药赚钱"）。TA 总结：平台积分耗尽 ≠ 立即断线，执行中的任务和分段 bash 能继续跑——"干活后付费"机制存在可挤的兜底余量。

## 原理
计费与执行解耦的架构里，"停止指令"和"停止执行"之间有时间差和任务粒度差；把任务切到结算边界内，就能把余量压到极限。注意区分：Coze 是这条机制，Codex/Claude 是 5 小时滚动计费，逻辑不同，别混。

## 双向启示
- 设计按时计费产品时：注意结算边界期的执行余量，要么掐得更死，要么明确免责（我们的 skill v1.4 免责条款"挂机会持续消耗额度"正是为这种场景兜底）
- 使用者视角：AI 平台的"自我保护机制"（长任务链被 token 截断）反而是挂机天花板——分段存档续跑是破解法
